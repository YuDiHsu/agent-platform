# 04: 個人 OBO 權杖加密金庫（AES-256-GCM）與動態角色／工具向量檢索（Tool RAG）

**What to build:** 建立企業零信任身分驗證、個人外部連接器權杖加密金庫（Token Vault），以及基於 `pgvector` HNSW 的動態角色與工具檢索器（Dynamic Role & Tool RAG）。每位使用者的 OAuth2 On-Behalf-Of（OBO）或信箱憑證在寫入資料庫前，均以獨立隨機 Nonce 的 AES-256-GCM 加密保護，並僅能由該使用者本人的執行上下文解密取用；同時，編排器在每回合對話根據使用者問題的嵌入向量（依 `ADR-0001` 由可配置之 Embedding 模型產生），結合使用者身分與部門可見度範圍（`PRIVATE`, `DEPARTMENT`, `GLOBAL`），動態檢索最相關的候選角色，並將單一角色每回合注入的工具定義數量上限控制在 Top-5，避免工具描述塞爆模型 Context。

**Blocked by:** 01: 平台最小可行骨架、13 表資料庫遷移與內建角色/規範/技能種子載入

**Status:** ready-for-agent

- [ ] 權杖金庫採用 AES-256-GCM 與每筆紀錄獨立隨機 Nonce 加解密存取權杖與重新整理權杖，密文遭竄改時拋出驗證失敗例外（`REQ-006`, `REQ-012`）
- [ ] 認證中介層解析當前請求之使用者身分與部門，並提供僅限本人取用的 OBO 權杖讀取介面，禁止跨使用者讀取他人權杖（`REQ-012`）
- [ ] 前端連接器設定頁面與後端端點支援檢視及綁定個人的企業連接器授權狀態
- [ ] 動態檢索器使用 `pgvector` 餘弦距離（`<=>`）檢索候選角色與可用工具，嚴格過濾 `visibility_scope`（僅回傳 `GLOBAL`、同部門 `DEPARTMENT` 或本人建立之 `PRIVATE` 項目）（`REQ-009`, `REQ-012`）
- [ ] 單一角色每回合動態注入之工具數量硬性上限為 Top-5（`TC-M2-03`）
